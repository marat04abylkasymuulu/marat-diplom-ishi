КИРИШ СӨЗ

Теманын актуалдуулугу

Азыркы заманда маалыматтык технологиялар билим берүү тармагына тереңден кирип, окутуунун сапатын жогорулатуу менен бирге, окуу борборлорунун иш процесстерин автоматташтыруу зарылдыгын жаратууда. Кыргызстандагы көптөгөн жеке окуу борборлору, анын ичинде ЖРТ/ОРТ (Жалпы Республикалык Тестирлөө / Общереспубликанское Тестирование) даярдоо борборлору, азырынча ата-энелер менен байланышууда, курстар жөнүндө маалымат жайылтууда жана студенттерди каттоодо заманбап санариптик куралдарды толук колдоно элек.

«Рекорд» окуу борбору — Ош шаарында 8 жылдан ашык тажрыйбасы бар, 200 ден ашык балл алган окуучулар менен алтын сертификаттарга ээ болгон ЖРТ/ОРТ даярдоо борбору. Бирок, борбордун маалыматтарын коомчулукка жана потенциалдуу студенттерге жеткирүү үчүн заманбап веб-тиркеме жок эле. Бул дипломдук иштин негизги максаты ушул маселелерди чечүү болуп саналат.

Бүгүнкү күндө Single Page Application (SPA) технологиялары, RESTful API'лер, контейнеризация (Docker) жана үзгүлтүксүз интеграция/жеткирүү (CI/CD) ыкмалары заманбап веб-иштеп чыгуунун стандарттарына айланган. Бул ыкмаларды колдонуу менен иштелген тиркеме масштабдуу, коопсуз жана колдонууга ыңгайлуу болот.

Дипломдук иштин максаты

«Рекорд» окуу борбору үчүн толук функционалдуу, көп тилдүү, заманбап full-stack веб-тиркеме иштеп чыгуу. Тиркеме коомдук сайт (студенттер жана ата-энелер үчүн) жана администрация панели (кызматкерлер үчүн) деген эки негизги бөлүктөн турат.

Дипломдук иштин милдеттери

Коюлган максатка жетүү үчүн төмөнкү милдеттер аныкталган:

  1. Окуу борборунун иш процесстерин талдоо жана техникалык тапшырма түзүү;
  2. Системанын архитектурасын долбоорлоо (backend, frontend, маалымат базасы);
  3. Django REST Framework менен RESTful API иштеп чыгуу;
  4. React жана Vite менен SPA тиркемесин иштеп чыгуу;
  5. Көп тилдүүлүк системасын (кыргызча, орусча, англисче) ишке ашыруу;
  6. JWT аутентификация менен админ панелди ишке ашыруу;
  7. WhatsApp жана Email интеграциялоо;
  8. Автоматташтырылган тесттер жазуу;
  9. Docker менен контейнеризациялоо жана CI/CD пайплайн түзүү;
  10. Тиркемени Render.com платформасында деплой кылуу.

Изилдөөнүн предмети

Full-stack веб-тиркемени иштеп чыгуунун методологиялары жана технологиялары.

Иштин практикалык мааниси

Иштелген веб-тиркеме реалдуу окуу борбору тарабынан колдонулуп, борбордун маалыматтык ачыктыгын жогорулатат, администрациянын жумушун жеңилдетет, жана потенциалдуу студенттер менен байланышты оңойлотот. Тиркеме https://record-frontend-f76k.onrender.com дарегинде жеткиликтүү.

Иштин структурасы

Дипломдук иш кириш сөздөн, 4 бөлүмдөн, корутундудан, колдонулган адабияттар тизмесинен жана тиркемелерден турат. Биринчи бөлүм теориялык негиздерге арналган. Экинчи бөлүмдө системанын архитектурасы долбоорлонот. Үчүнчү бөлүм ишке ашыруунун деталдарын камтыйт. Төртүнчү бөлүмдө тестирлөө жана деплой процесстери каралат.

I БӨЛҮМ. ТЕОРИЯЛЫК НЕГИЗДЕР

1.1. Веб-тиркемелер жана алардын түрлөрү

Веб-тиркеме — бул колдонуучу веб-браузер аркылуу колдоно алган программалык камсыздоо. Салттуу десктоп тиркемелерден айырмаланып, веб-тиркемелер орнотууну талап кылбайт жана каалаган түзмөктөн (компьютер, телефон, планшет) жеткиликтүү.

Заманбап веб-тиркемелер бир нече түргө бөлүнөт:

Статикалык веб-сайттар

HTML, CSS жана JavaScript файлдарынан турган, серверде эч кандай иштетүүсүз түздөн-түз колдонуучуга жиберилген веб-барактар. Мисалы: портфолио сайттар, визитка-сайттар.

Динамикалык веб-тиркемелер (Server-Side Rendering)

Сервер тарабында HTML генерацияланып, ар бир суроо боюнча баракча кайра курулат. Мисалы: WordPress, традициялуу Django шаблондор.

Single Page Application (SPA)

Бир HTML баракчасы жүктөлүп, андан кийин JavaScript аркылуу бардык мазмун динамикалык түрдө жаңыланат. Бет жаңыртуусуз контент өзгөрөт — бул колдонуучу тажрыйбасын мобилдик тиркемеге жакындатат. React, Vue.js, Angular сыяктуу фреймворктор SPA түзүүнүн негизги куралдары.

Биздин долбоордо SPA архитектурасы тандалган, анткени:

  • Колдонуучу тажрыйбасы жагымдуу — бет жаңыртуулары жок;
  • Frontend жана Backend бөлүнгөн — параллель иштеп чыгууга мүмкүнчүлүк;
  • API аркылуу кийинчерээк мобилдик тиркеме кошуу оңой;
  • Статик файлдарды CDN аркылуу тез жеткирүү мүмкүн.

1.2. Full-stack иштеп чыгуунун принциптери

Full-stack иштеп чыгуу — бул веб-тиркеменин бардык катмарларын (frontend, backend, маалымат базасы, инфраструктура) бир иштеп чыгуучу же команда тарабынан ишке ашыруу. Бул ыкманын артыкчылыктары:

  • Бирдиктүү көз караш: Системанын бардык бөлүктөрүн түшүнгөн адам архитектуралык чечимдерди жакшыраак кабыл алат;
  • Тезирээк иштеп чыгуу: Бир адам frontend менен backend ортосундагы интеграцияны тездетет;
  • Акыркы колдонуучуга көңүл буруу: Техникалык чечимдер колдонуучу тажрыйбасына негизделет.

1.3. REST API архитектурасы

REST (Representational State Transfer) — бул веб-сервистерди долбоорлоо үчүн архитектуралык стиль. Roy Fielding тарабынан 2000-жылы докторлук диссертациясында сунушталган.

REST принциптери:

  1. Клиент-сервер: Frontend жана Backend бөлүнгөн, бири-бирине көз каранды эмес;
  2. Абалсыздык (Stateless): Ар бир суроо толук маалыматты камтыйт, сервер клиенттин абалын сактабайт;
  3. Кэштөө: Жоопторду кэштөө мүмкүнчүлүгү бар;
  4. Бирдиктүү интерфейс: Стандарттуу HTTP методдору (GET, POST, PUT, DELETE) колдонулат;
  5. Катмарлуу система: Клиент аралык серверлер (прокси, балансировщик) бар экенин билбейт.

1.4. Колдонулган технологияларды талдоо

Backend: Django жана Django REST Framework

Django — Python тилинде жазылган жогорку деңгээлдеги веб-фреймворк. «Батарейкалар менен» («batteries included») философиясы менен, Django ORM, аутентификация, админ панель, миграциялар сыяктуу компоненттерди камтыйт. Django REST Framework (DRF) — Django'нун үстүнө курулган RESTful API түзүү үчүн күчтүү тулкит.

Django тандалган себептер:

  • Python — окууга оңой, жаңы баштагандар үчүн жеткиликтүү;
  • Коопсуздук — CSRF, XSS, SQL инъекция коргоолору камтылган;
  • ORM — SQL жазбай маалымат базасы менен иштөө;
  • Миграциялар — маалымат базасынын схемасын версиялоо;
  • Чоң коомчулук — көптөгөн пакеттер жана документация.

Frontend: React 19

React — Facebook (Meta) тарабынан иштелген JavaScript китепканасы. Компоненттик архитектурага негизделген, Virtual DOM менен тез рендерлейт.

React тандалган себептер:

  • Компоненттик архитектура — кайра колдонууга ылайыктуу UI бөлүктөрү;
  • Чоң экосистема — react-router, react-i18next, axios ж.б.;
  • Жумуш базарында эң талап кылынган frontend технология;
  • Hooks — функционалдык компоненттерде state башкаруу.

Vite — Build куралы

Vite — заманбап frontend build куралы. Webpack'тен айырмаланып, HMR (Hot Module Replacement) абдан тез иштейт, нативдик ES модулдерин колдонот.

Tailwind CSS

Utility-first CSS фреймворку. Класстарды HTMLде түздөн-түз жазуу менен стилдөө — бул ыкма тез прототиптөө жана дизайн системаларды курууга ылайыктуу.

PostgreSQL

Дүйнө жүзүндө эң популярдуу ачык булактуу реляциялык маалымат базасынын башкаруу системасы (РМББС). ACID транзакциялары, JSON колдоосу, толук текст издөө жана масштабдуулук менен белгилүү.

Docker

Контейнеризация платформасы. Тиркемени бардык зависимостылары менен бирге изоляцияланган контейнерге салат — «менин машинамда иштейт» маселесин чечет.

GitHub Actions

CI/CD (Continuous Integration / Continuous Deployment) куралы. Код push кылганда автоматтуу тесттер, build жана деплой процесстерин ишке ашырат.

2.5. Коопсуздук архитектурасы (JWT)

JSON Web Token (JWT) — бул коопсуз маалымат алмашуу үчүн стандарт (RFC 7519). Биздин системада админ панелдин аутентификациясы үчүн колдонулат.

JWT иштөө принциби:

  1. Колдонуучу логин/паролду жөнөтөт → POST /api/admin/token/
  2. Сервер текшерет → Access Token (12 саат) + Refresh Token (7 күн) кайтарат;
  3. Ар бир суроодо Access Token Authorization: Bearer <token> header'де жөнөтүлөт;
  4. Access Token мөөнөтү бүтсө, Refresh Token менен жаңысы алынат;
  5. Refresh Token мөөнөтү бүтсө, кайра логин болуу керек.

Артыкчылыктары:

  • Сервер тарабында сессия сактоо зарылдыгы жок (stateless);
  • Горизонталдык масштабдоого ылайыктуу;
  • Мобилдик тиркемелерде дагы иштейт.
[ 2.5-сүрөт: JWT аутентификация агымынын диаграммасы ]

Client → POST /token (username, password) → Server
Server → {access_token, refresh_token} → Client
Client → GET /api/admin/courses (Authorization: Bearer token) → Server
Server → {data} → Client

const AuthContext = createContext();

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);

  const login = async (username, password) => {
    const { data } = await adminApi.post('/token/', {
      username, password
    });
    localStorage.setItem('access_token', data.access);
    localStorage.setItem('refresh_token', data.refresh);
    // Колдонуучу маалыматын алуу
    const userRes = await adminApi.get('/me/');
    setUser(userRes.data);
  };

  const logout = () => {
    localStorage.removeItem('access_token');
    localStorage.removeItem('refresh_token');
    setUser(null);
  };

  return (
    <AuthContext.Provider value={{ user, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

4.2. Docker контейнеризация

Docker — тиркемени бардык зависимостылары менен бирге изоляцияланган контейнерге салуу технологиясы. «Менин машинамда иштейт» маселесин чечет.

Backend Dockerfile

FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1
WORKDIR /app

RUN apt-get update && apt-get install -y --no-install-recommends \
    libjpeg-dev zlib1g-dev && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .

COPY entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh
EXPOSE 8000
ENTRYPOINT ["/entrypoint.sh"]

Frontend Dockerfile (Multi-stage build)

# 1-этап: Build
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# 2-этап: Serve
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Multi-stage build колдонулганда акыркы image өлчөмү кичирейет (Node.js кереги жок, Nginx гана калат).

4.3. CI/CD пайплайн (GitHub Actions)

Continuous Integration / Continuous Deployment — код өзгөргөндө автоматтуу тесттер жана деплой процесси. Биздин системада GitHub Actions колдонулат.

Пайплайн агымы

Push to main
    │
    ├── test-backend (Python 3.12)
    │   └── python manage.py test
    │
    ├── test-frontend (Node.js 20)
    │   ├── npm test -- --run
    │   └── npm run build
    │
    └── build-and-push (main гана)
        ├── Docker login
        ├── Build backend image → push to Docker Hub
        └── Build frontend image → push to Docker Hub

GitHub Actions конфигурациясы (.github/workflows/ci.yml)

name: CI/CD Pipeline
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test-backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
        working-directory: backend
      - run: python manage.py test --verbosity=2
        working-directory: backend

  test-frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
      - run: npm ci
        working-directory: frontend
      - run: npm test -- --run
        working-directory: frontend

  build-and-push:
    needs: [test-backend, test-frontend]
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: docker/login-action@v3
      - uses: docker/build-push-action@v5
        with:
          context: ./backend
          push: true
          tags: alidin/record-backend:latest

GitHub → Actions табында 3 job көрүнүп турат:

✅ test-frontend (passed)
✅ build-and-push (completed)

4.4. Render.com'до деплой

Render.com — заманбап булут платформа, веб-тиркемелерди, маалымат базаларын жана статик сайттарды хостинг кылуу үчүн. Blueprint файлы аркылуу бүт инфраструктураны коддо аныктоо мүмкүн (Infrastructure as Code).

render.yaml — Blueprint

databases:
  - name: record-db
    plan: free
    databaseName: record_education

services:
  - type: web
    name: record-backend
    runtime: python
    plan: free
    rootDir: backend
    buildCommand: ./build.sh
    startCommand: gunicorn config.wsgi:application --bind 0.0.0.0:$PORT
    envVars:
      - key: DATABASE_URL
        fromDatabase:
          name: record-db
          property: connectionString
      - key: SECRET_KEY
        generateValue: true

  - type: web
    name: record-frontend
    runtime: static
    rootDir: frontend
    buildCommand: npm ci && npm run build
    staticPublishPath: dist
    routes:
      - type: rewrite
        source: /api/*
        destination: https://record-backend-awf3.onrender.com/api/*

Деплой процесси

  1. GitHub'ка код push кылуу;
  2. Render автоматтуу build баштайт;
  3. Backend: зависимостылар орнотуу → миграция → admin түзүү → gunicorn баштоо;
  4. Frontend: npm ci → build → статик файлдарды жарыялоо;
  5. Healthcheck өткөндөн кийин сервис «Live» статусуна өтөт.
